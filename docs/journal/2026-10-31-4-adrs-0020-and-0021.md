# 2026-10-31 (4) — the stance review's two ADRs: IndexedDB now, pnpm 12 next

The [stance review](../reviews/2026-10-31-stance-review.md) proposed two ADRs and left them for
Ryan; he asked for both.

**[ADR-0020](../adr/0020-indexeddb-is-the-store-ahead-of-the-sync-decision.md)** records what
was built on 2026-07-10 and lived only in a journal: the event log is in IndexedDB, ahead of
the sync decision, not after it as ADR-0003 said. Checked against the code first: database
`cycle-in`, store `events` keyed by `id`, `put` per append (so replaying any payload is
harmless), and the in-memory store used only where `indexedDB` is undefined (`src/main.ts`).
It supersedes ADR-0003's storage paragraph only; ADR-0003's Status stays Accepted (the hygiene
check allows a bare `Accepted` or a whole-ADR supersession, and the main decision stands), and
its index row says which paragraph. Two consequences it names that weren't written anywhere:
data is per origin until a sync or a bundle moves it, and the browser may evict it without
persistent storage, which isn't requested.

**[ADR-0021](../adr/0021-move-to-pnpm-12.md)** decides the move to pnpm 12, as its own change:
`packageManager`, `engines.pnpm` from `>=9.0.0` to `>=12`, and the lockfile regenerated, so the
diff reads as a format change. It writes down the trial's finding that a frozen install fails
when only `packageManager` moves, and the gates the trial couldn't run (CI, audit, signatures,
licences, OSV). A first draft claimed Renovate would fail the same way; that was untested
(Renovate regenerates lockfiles itself), so the ADR now says only what's known.
